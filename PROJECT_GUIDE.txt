2. HOW TO OPEN AND PLAY
================================================================================
  1. Open the project folder in Unity Hub with Unity 6000.6.0f1.
  2. Open Assets/Scenes/SampleScene.unity.
  3. Press Play.

  LEON (player 1 - keyboard):
      Move ........ A / D  or  Left / Right arrow
      Jump ........ Space
      Attack ...... Left mouse button  or  F
      Push ........ Hold E
      Cancel push . A  (or steer against the push direction)

  KRUSH (player 2 - gamepad):
      Move ........ Left stick
      Jump ........ A / Cross (South button)
      Push ........ Hold RB / Right Shoulder
      Attack ...... none (by design)

  The Skeleton patrols and attacks Leon. Five skeleton hits kill a player.
  Leon's sword kills the Skeleton in five hits. Krush has no attack.

  To test pushing, enable the Push_object GameObject in the Hierarchy first,
  because it starts inactive.

7. LEON - EVERY MECHANIC
================================================================================
Leon is the complete character: movement, jump, sword combo, push, hurt and
death. He is bound to the keyboard only, so the gamepad belongs to Krush.

--------------------------------------------------------------------------------
7.1 Movement
--------------------------------------------------------------------------------
  Script: PlayerMovement2D
  Input mode: KeyboardOnly

  Horizontal input comes from A / D or the Left / Right arrow keys.
  The character accelerates toward moveSpeed (3 units/s) with acceleration 55.
  Releasing input decelerates at 40.
  Turning around uses turnSpeed 90, which is deliberately much higher than the
  acceleration, so Leon pivots instantly instead of sliding backwards.

  The Rigidbody2D is set to NeverSleep in Awake, because a sleeping body would
  ignore linearVelocity assignments and freeze the character.

  While in the air, movement is still allowed (air control):
      - acceleration is 70% of ground acceleration
      - deceleration is 50% of ground deceleration
      - reversing direction uses the full turnSpeed

--------------------------------------------------------------------------------
7.2 Grounding
--------------------------------------------------------------------------------
  The ground check is a box probe that straddles the bottom of Leon's collider.
  It is not a single ray, so it still works while the sprite changes frame or
  scale.

  Probe values:
      groundTag ............ "Ground"
      groundProbeDepth ..... 0.25
      groundProbeLift ...... 0.06
      groundProbeWidth ..... 0 (derived as 75% of the collider width)
      fallback offset ...... -0.89 (only if there is no collider)
      fallback radius ...... 0.15

  The probe runs in both Update (so the Animator has a fresh value every render
  frame) and FixedUpdate (so movement decisions use the physics state).

  The character's own collider is always ignored when looking for ground.

--------------------------------------------------------------------------------
7.3 Jump
--------------------------------------------------------------------------------
  Jump is read from Space (keyboard only, because Leon is KeyboardOnly).

  jumpForce ................ 8
  fallGravityScale ......... 1.5  (extra gravity while falling)
  coyoteTime ............... 0.1 s
  jumpParameter ............ "IsJumping" (bool)

  Jump input is queued and executed in FixedUpdate. A jump is allowed only if:
      - the character is not attacking
      - the character is not pushing
      - coyote time is still available (grounded within the last 0.1 s)

  While airborne, the Speed parameter is forced to 0 so the Run animation never
  plays in mid-air. The IsJumping bool is set to "not grounded".

  A 0.1 s jump-input cooldown prevents double-taps from firing twice.

--------------------------------------------------------------------------------
7.4 Run animation sync
--------------------------------------------------------------------------------
  speedParameter ........... "Speed" (float, 0 = idle, 1 = full run)
  runThreshold ............. 0.1
  animationReferenceSpeed .. 3.878
  syncRunToSpeed ........... 1 (full sync)
  minRunPlaybackSpeed ...... 0.5
  maxRunPlaybackSpeed ...... 3

  The run clip was authored for a ground speed of 3.878 units/s. The Animator's
  playback speed is scaled by (actual speed / 3.878), clamped between 0.5 and 3.
  This keeps the stride length constant, so the feet do not slide at different
  speeds.

  While attacking, pushing or hurt, Animator speed is reset to 1 and the action
  clip owns the body.

--------------------------------------------------------------------------------
7.5 Facing
--------------------------------------------------------------------------------
  Facing is driven by movement input, not by velocity. That way an enemy shoving
  Leon cannot turn him away from the enemy.

  The sprite art faces right, so facing left sets SpriteRenderer.flipX = true.

  FaceDirection(delta) is a public method used by the attack assist to snap Leon
  toward the nearest enemy when a swing starts.

--------------------------------------------------------------------------------
7.6 Sword attack (combo)
--------------------------------------------------------------------------------
  Script: PlayerAttack2D
  Inputs: Left mouse button, or F. Gamepad attack is DISABLED.
  Animation parameter: "Attack" (int): 0 = neutral, 1 = Attack1, 2 = Attack2.

  Combo flow:
      - First press starts Attack1.
      - Pressing again during a swing queues Attack2. The queued step is written
        straight to the Animator parameter; exit-time transitions decide when
        the follow-up actually starts.
      - After a swing ends, the combo stays open for comboBufferTime = 0.35 s,
        so a slightly late press continues the chain instead of restarting.
      - releaseLeadTime = 0.08 s clears the parameter just before the exit-time
        transition, so Idle/Run cannot re-enter the same swing and freeze on the
        last frame.
      - swingStartLockTime = 0.1 s locks movement from the moment a swing is
        requested, before the Animator enters the state.

  Damage:
      - Damage is dealt ONLY by the "OnAttackHitFrame" animation event, placed
        on the exact contact frame of each clip.
      - Attack1 has one hit event at 0.375 s.
      - Attack2 has two hit events at 0.45 s and 0.75 s.
      - Each swing has a unique swingSequence number, and the number of allowed
        hits is counted from the clip's own events, so one swing can never deal
        unlimited damage.
      - Hit detection is an OverlapCircleAll in front of Leon:
            attackHitRange ....... 2.0
            comboHitReachBonus ... 0.5 (extra reach on follow-up hits)
            attackHitHeight ...... 2.0
            enemyLayerMask ....... Everything
      - The target must be in front of Leon and within horizontal and vertical
        reach. If it has a SkeletonAI, TakeSwordHit is called.
      - When a swing starts, FaceNearestEnemy turns Leon toward the closest
        living enemy within range.

  Movement lock:
      - While IsSwinging, movement decelerates at attackLockDeceleration = 250,
        so Leon plants his feet almost immediately.
      - The lock ends the instant the Animator leaves the attack state, not on a
        timer.

--------------------------------------------------------------------------------
7.7 Push
--------------------------------------------------------------------------------
  Leon's push lives inside PlayerAttack2D (the push half, without a separate
  script).

  Inputs:
      - Hold E (keyboard).
      - Gamepad push is DISABLED for Leon.
      - Cancel with A, the Left arrow key, or by steering against the push
        direction.

  Rules:
      - A push starts only when a collider tagged "PushObject" is within
        pushRange = 1 (gap between colliders) and is in front of Leon.
      - The search radius is 6 units.
      - pushStrength = 2 units/s.
      - The push direction is locked to the way Leon is facing at the moment the
        push starts. It can never turn into a backwards shove.
      - The Push animation plays for as long as E is held.
      - Animation events OnPushStart (time 0) and OnPushEnd (time 1.15) gate when
        the object actually moves.
      - After OnPushEnd the object stops for pushEndHoldDuration = 0.2 s, then
        the animation restarts from 0 for a seamless loop.
      - Releasing the button ends the push immediately.
      - Stepping off the ground ends the push.
      - A cancel latches until the button is released, so holding E cannot
        restart the push every frame.
      - While pushing, movement is forced to PushDirection * pushStrength, so
        Leon walks forward with the object.

--------------------------------------------------------------------------------
7.8 Hurt and death
--------------------------------------------------------------------------------
  Script: PlayerHealthHurt
  hitsBeforeDeath = 5 (the fifth hit is the killing hit)
  Debug hurt key = H, DISABLED by default (enemies are the real damage source).

  Hurt:
      - TakeHit() increments hurtCount.
      - If the count is below 5, the Hurt trigger plays.
      - Movement is locked on the same frame the hit lands (0.3 s grace timer
        covers the frame between setting the trigger and entering the state).
      - Movement stays locked for as long as the Animator is in the "Hurt"
        state.
      - A stray Death trigger is reset before playing Hurt.

  Death:
      - On the fifth hit, Die() runs.
      - The ground line is captured first (see below).
      - The Death trigger plays. The Hurt trigger is reset first so it cannot
        interrupt Death.
      - PlayerMovement2D is disabled.
      - PlayerAttack2D is disabled (Leon only).
      - Rigidbody2D velocity is zeroed and simulated = false.
      - LateUpdate pins the visible bottom of the death sprite to the captured
        ground line, so the corpse does not float as the frames get shorter.

  Ground capture:
      - If the player is grounded, the ground line is the bottom of the collider.
      - If the player dies in mid-air, a downward RaycastAll finds the highest
        collider tagged "Ground" below the player.
      - If no ground is found, the collider bottom is used.

--------------------------------------------------------------------------------
7.9 Player-vs-player pass-through
--------------------------------------------------------------------------------
  Script: PlayerSeparation2D (also on Krush).
  See section 13 for the full mechanism.


================================================================================
8. KRUSH - EVERY MECHANIC
================================================================================
Krush is a full second character built to mirror Leon's movement, jump, push,
hurt and death, but with NO attack. She is controller-only.

--------------------------------------------------------------------------------
8.1 Movement
--------------------------------------------------------------------------------
  Script: PlayerMovement2D
  Input mode: GamepadOnly, gamepadIndex 0 (the active gamepad).
  moveSpeed = 4 (Leon uses 3).

  Everything else is identical to Leon:
      acceleration 55, deceleration 40, turnSpeed 90,
      air control, jump force 8, fall gravity 1.5, coyote 0.1,
      the same box ground probe and the same run-animation speed sync.

  Move input: left stick X. A deadzone of 0.15 kills stick drift.
  Jump input: A / Cross (South button).

--------------------------------------------------------------------------------
8.2 Push
--------------------------------------------------------------------------------
  Script: PlayerPush2D (this is Leon's push logic without the sword combo).

  Inputs:
      - Hold RB / Right Shoulder (pushGamepadButton = RightShoulder).
      - Keyboard push is DISABLED.
      - Cancel with the configured cancel key (A) or by steering against the
        push direction.

  Rules (one-for-one with Leon's push):
      - Starts only when a "PushObject"-tagged collider is within pushRange = 1
        and in front of Krush.
      - pushSearchRadius = 6.
      - pushStrength = 2.
      - Direction is locked to Krush's facing at push start.
      - Push animation plays while the button is held.
      - OnPushStart (0 s) and OnPushEnd (1.15 s) gate object movement.
      - End hold = 0.2 s, then the animation restarts from 0.
      - Releasing RB ends the push.
      - Leaving the ground ends the push.
      - Steering against the push direction cancels it, and the cancel latches
        until RB is released.
      - While pushing, movement is forced forward at pushStrength.

--------------------------------------------------------------------------------
8.3 Hurt and death
--------------------------------------------------------------------------------
  Same PlayerHealthHurt component as Leon:
      - 5 hits to die.
      - Hurt locks movement for the duration of the Hurt state.
      - Death disables movement, zeroes velocity and sets simulated = false.
      - The corpse is pinned to the ground.
      - Krush has no attack component, so there is nothing to disable there.

--------------------------------------------------------------------------------
8.4 Animation
--------------------------------------------------------------------------------
  Controller: Assets/Animations/Krush/Krush.controller
  States: Idle, Run, Jump, Push, Hurt, Death.
  There is also an unused "Krush-Shot" state in the working tree (see section
  29); it is not used by gameplay.

  Parameters:
      Speed (float)
      Push (int)
      IsJumping (bool)
      Hurt (trigger)
      Death (trigger)

  Run timing was matched exactly to Leon:
      Krush-Run: 12 fps, 2.0833 s, 25 keyed sprite frames (same as Leon-Run).

  Krush has no Attack parameter and no Attack states.

--------------------------------------------------------------------------------
8.5 Player-vs-player pass-through
--------------------------------------------------------------------------------
  Same PlayerSeparation2D component as Leon. See section 13.

--------------------------------------------------------------------------------
8.6 What Krush does NOT have
--------------------------------------------------------------------------------
  - No sword.
  - No attack input, no Attack parameter, no attack states, no damage code.
  - No gamepad attack or keyboard push; she is controller-only.
  - The bow and shoot sprites in Assets/Sprites/Krush spritesheets are unused.

9. LEON vs KRUSH - SHARED AND DIFFERENT
================================================================================
SHARED (same script or same behaviour):
  - PlayerMovement2D for run, air control, jump, coyote time, grounding,

10. SHARED PLAYER MECHANIC 1: MOVEMENT AND JUMPING
================================================================================
  Script: Assets/Scripts/Player/PlayerMovement2D.cs
  Execution order: -100 (runs before normal scripts).

  Public properties:
      IsGrounded ....... true while standing on a collider tagged Ground
      IsLocked ......... true while attacking, pushing or hurt
      FacingRight ...... true while facing right
      IsAttacking ...... set by the attack script
      IsPushing ........ set by the push script
      PushDirection .... +1 right / -1 left while pushing
      PushSpeed ........ speed while pushing
      IsHurt ........... set by PlayerHealthHurt
      InputMode ........ the device mode
      FeetPosition ..... world position of the bottom of the collider

  Update:
      1. Read horizontal input (keyboard then gamepad override).
      2. Refresh IsGrounded.
      3. Update coyote counter.
      4. Read jump input and queue it.
      5. If not locked, update facing from input and flip the sprite.
      6. Set Animator Speed (0 while airborne).
      7. Set Animator IsJumping.
      8. If locked, reset Animator speed to 1 and return.
      9. Otherwise scale Animator speed from actual velocity.

  FixedUpdate:
      1. Re-check IsGrounded.
      2. Execute a queued jump.
      3. Apply extra fall gravity if falling.
      4. If hurt: zero horizontal velocity and return (highest priority).
      5. If pushing: force velocity = PushDirection * PushSpeed and return.
      6. If attacking: decelerate hard toward zero and return.
      7. If airborne: move toward air target speed with air rates.
      8. If grounded: move toward input * moveSpeed, using turnSpeed when
         reversing, acceleration when speeding up, deceleration when stopping.
      9. Wake the body when there is input.

  Lock priority: Hurt > Push > Attack.

  ReadHorizontalInput:
      - Keyboard A / Left arrow gives -1.
      - Keyboard D / Right arrow gives +1.
      - Gamepad left stick overrides the keyboard when its magnitude is above
        the 0.15 deadzone.
      - The result is clamped to -1..1.

  ActiveGamepad:
      - Returns null for KeyboardOnly.
      - gamepadIndex 0 returns Gamepad.current (the active pad).
      - gamepadIndex > 0 returns Gamepad.all[index].

11. SHARED PLAYER MECHANIC 2: PUSHING
================================================================================
  There are two push scripts with the same rules:
      PlayerAttack2D ... Leon: push + sword combo.
      PlayerPush2D ..... Krush: push only.

  PushableObject2D:
      - The prop stores a pending delta.
      - Push(direction, distance) flattens the direction to X, normalizes it,
        adds it to the pending delta, records LastPushDirection and sets
        IsBeingPushed.
      - FixedUpdate applies the pending delta with Rigidbody2D.MovePosition, so
        the prop slides smoothly and pushes dynamic bodies out of the way.
      - The prop is set to NeverSleep so a later push is never swallowed.
      - StopPush() clears the pending delta.

  Why a push is forward-only:
      - The direction is locked when the push starts, from the character's
        facing.
      - The target must be on the same side as that facing, otherwise the push
        is rejected.
      - Steering against the locked direction cancels the push.

  Animation-event gating:
      - OnPushStart sets pushIsActive = true, so the object moves.
      - OnPushEnd sets pushIsActive = false and starts the end-hold timer.
      - After the hold, the animation restarts from time 0 and movement resumes.

  Scene tag:
      Push_object has the tag "PushObject".
      The prop starts inactive; enable it to test pushing.

13. SHARED PLAYER MECHANIC 4: PLAYER-VS-PLAYER PASS-THROUGH
================================================================================
  Script: Assets/Scripts/Player/PlayerSeparation2D.cs
  Added to both Leon and Krush.

  Goal:
      The two players must not collide at all. They can stand on the same spot,
      walk through each other and jump through each other, and neither one ever
      blocks, bounces off or nudges the other.

  How it works:
      1. COLLISION PAIR IS SWITCHED OFF
         In Start/ResolvePair, each player calls
             Physics2D.IgnoreCollision(myCollider, otherCollider, true)
         so the Rigidbody2D solver ignores that one collider pair completely.

      2. NO POSITIONAL CORRECTION
         The component does not move either body and has no push-apart code.
         Overlap is allowed, so the players simply pass through one another.

      3. WORLD COLLISION IS UNTOUCHED
         Both players still collide normally with the ground, walls, the
         Skeleton and pushable props. Only the player-vs-player pair is ignored.

  Inspector fields:
      other ................. the other player's PlayerSeparation2D

  Pair resolution:
      - If "other" is empty, the script finds the other PlayerSeparation2D.
      - It waits until the other component has run Awake.
      - It calls IgnoreCollision once, then marks the pair ready.

  Test results:
      - Collision ignored Leon <-> Krush: true in both directions.
      - Krush walks through Leon: Krush crossed to the other side (16.966
        units) with a 0.507 maximum overlap; Leon did not move.
      - Both standing on the same spot: stayed stacked with a 0.538 overlap,
        no push-apart.
      - Sprite draw order while overlapping: Leon 4, Krush 3, distinct and
        unchanged after the pass-through.

14. ENEMY - SKELETON, EVERY MECHANIC
================================================================================
  Script: Assets/Scripts/Enemy/SkeletonAI.cs
  Controller: Assets/Animations/Enemies/Skeleton/Skeleton.controller
  Physics material: Assets/Physics/SkeletonFrictionless.physicsMaterial2D

  The Skeleton has no Animator parameters. It plays states by name through
  animator.Play(stateName, 0, 0f), with a playback speed chosen per state.

--------------------------------------------------------------------------------
14.1 State machine
--------------------------------------------------------------------------------
  States: Idle, Patrol, Chase, Attack, Hurt, Dead.

  Idle:
      - Stands still for idleTime = 2 s.
      - If the player is alive and within detectionRange, enters Chase.
      - Otherwise enters Patrol.

  Patrol:
      - Walks left and right between (startX - patrolDistance) and
        (startX + patrolDistance), patrolDistance = 1.
      - walkSpeed = 3.
      - Walk animation playback is synced to speed using
        walkAnimationReferenceSpeed = 3.8 and walkAnimationSync = 0.8.
      - At each end it reverses direction and idles for idleTime.
      - If the player is within detectionRange, enters Chase.

  Chase:
      - If the player is dead or farther than loseTargetRange = 6, goes back to
        Idle.
      - If the player is within attackRange = 1.5 horizontally, stops, faces the
        player and plays Idle while waiting for the attack cooldown.
      - Otherwise walks toward the player at chaseSpeed = 3, with the Walk clip
        sped up (max 2x).

  Attack:
      - Alternates Attack1 and Attack2 on each attack.
      - attackDuration = 0.9 s.
      - attackAnimationSpeed = 0.75 (slower, so one swing reads at about Leon's
        swing length).
      - The hit lands after a delay:
            Attack1: attackHitDelay 0.32 s
            Attack2: attack2HitDelay 0.50 s
        The delay is divided by attackAnimationSpeed because the clip plays
        slower.
      - At the hit moment, TryHitPlayer checks:
            horizontal distance <= attackHitReach 1.9
            vertical difference <= 2
        If both pass and the player is not dead, playerHealth.TakeHit() is
        called.
      - After attackDuration, sets nextAttackTime = now + attackCooldown
        (2 s) and returns to Chase.

  Hurt:
      - Entered when Leon's sword hits.
      - The Skeleton is knocked away from the hit source:
            knockbackDistance = 0.6 over knockbackTime = 0.3 s
      - The knockback is integrated in FixedUpdate with a triangular speed
        curve, so it covers exactly 0.6 units regardless of frame rate.
      - hitStunTime = 0.35 s.
      - It turns back to face the attacker and plays TakeHit at 0.8x speed.
      - After the stun, it returns to Chase if the player is near, otherwise
        Idle.

  Dead:
      - Death is triggered by the fifth sword hit.
      - The ground line is captured before physics is disabled.
      - Plays Death at 0.6x speed.
      - Zeroes velocity, sets simulated = false and disables the collider.
      - LateUpdate pins the visible sprite bottom to the ground line, using
        deathArtBottomPadding = 0.49 to account for the transparent margin in
        the sheet.

15. PUSHABLE OBJECT
================================================================================
  Script: Assets/Scripts/Player/PushableObject2D.cs
  Scene object: Push_object (starts inactive)
  Tag: PushObject

  The prop is a dynamic Rigidbody2D with mass 50 and a 1x1 BoxCollider2D,
  scaled to about 2.15 x 3.0.

  Mechanism:
      - A push is accumulated during Update.
      - It is applied in FixedUpdate with MovePosition.
      - MovePosition slides the body instead of teleporting it, so the physics
        solver stays happy and pushes characters out of the way.
      - The prop only moves along the push direction.
      - The body never sleeps, so a later push is never lost.
      - Public state: IsBeingPushed, LastPushDirection.
      - Push(direction, distance) and StopPush() are the public API.

  Used by both Leon's PlayerAttack2D and Krush's PlayerPush2D.

  Krush when their sprites overlap. Swap the two values if Krush should be in
  front instead.

20. AGENTSCRIPTS (UNITY EDITOR AUTOMATION AND TESTS)
================================================================================
These files live in AgentScripts/ at the project root. They are editor-only
helpers and are not part of the game build. They are run through the Unity
Pipeline package with commands such as:

    unity command run_script --file AgentScripts/PlayTestKrush.cs --entry Run

  AttackVerify.cs
      Play-mode probes for sword hit timing and combo chaining. Every attack is
      triggered through the real Input System (key F), not by calling the combo
      method directly, so the whole input -> parameter -> Animator path is
      tested.

  BuildKrush.cs
      Idempotent builder for Krush. It:
        - slices the six Krush sprite sheets into animation clips with the same
          frame counts and sample rates as Leon (no attack clips),
        - builds Krush.controller (Idle, Run, Jump, Push, Hurt, Death),
        - adds the physics, movement, push, health and separation components to
          the Krush GameObject and wires every reference,
        - binds Leon to the keyboard and Krush to the gamepad.
      Entry point: BuildKrush.All.

  Inspect.cs
      General scene/asset inspection helper.

  InspectKrush.cs
      Inspects Krush's components, sprite, animator and scene state.

  PlayTest.cs
      Original Leon play-mode test suite: movement, attack, hurt, death,
      skeleton behaviour and status reporting.

  PlayTestKrush.cs
      Drives Krush with a synthetic gamepad in play mode and reports what the
      movement, jump, animation, push, hurt and death systems actually did.

  PlayTestSeparation.cs
      Play-mode check for PlayerSeparation2D: verifies that collision is ignored
      in both directions, that Krush can walk through Leon, that Leon is not
      nudged, and that two players can stand on the same spot.

  VerifySkeleton.cs
      Verifies the Skeleton controller, clips and sprite assets.

Typical test workflow:

    unity command editor_play
    unity command run_script --file AgentScripts/PlayTestSeparation.cs --entry PlayTestSeparation.Run --timeout_ms 120000
    unity command editor_stop

27. VERIFICATION AND TEST RESULTS
================================================================================
All of the following were checked in Play Mode through the Unity Pipeline
package.

Movement and animation:
  - Krush runs with the left stick, jumps with A and pushes with RB.
  - Krush's run animation timing matches Leon's (same 12 fps / 2.0833 s / 25
    keyed sprite frames).
  - Leon does not respond to the gamepad (no movement, no attack, no push).

Push:
  - Krush's push moved the pushable object about 1.26 units.
  - The push is forward-only and stops when the button is released.

Hurt and death:
  - Krush's Hurt locks movement and returns to Idle when it ends.
  - The fifth hit plays Death.
  - The corpse's visible bottom was pinned to -4.485 against a ground top of
    about -4.500, so it does not float.

Player-vs-player:
  - Physics2D.GetIgnoreCollision is true in both directions.
  - Krush walked through Leon and crossed to the other side (16.966 units)
    with a 0.507 maximum overlap; Leon did not move.
  - Both players standing on the same spot stayed stacked with a 0.538
    overlap, no push-apart.
  - Leon and Krush have different sprite sorting orders (Leon 4, Krush 3), so
    their draw order stays fixed while they overlap and no longer flickers.

Console:
  - No console errors or warnings after the final pass.

28. KNOWN LIMITATIONS AND POSSIBLE NEXT STEPS
================================================================================
  - One physical controller drives Krush; Leon is keyboard-only. Two-controller
    play needs gamepadIndex = 1 on Krush (or a second GamepadOnly player).

  - Krush has no attack by design. The bow/shoot sprites and the uncommitted
    Krush-Shot animator state are not used by gameplay.

  - PlayerMovement2D still contains Leon-specific comments/tooltips and an
    unused attackLockDeceleration path. Harmless for Krush but could be renamed.

  - The Leon controller file contains repeated Hurt/Death trigger parameter
    entries. Unity uses the first set; the duplicates are harmless but could be
    cleaned up.

  - The project has no UI, no audio clips and no tilemap gameplay yet. The
    SampleScene uses a single scaled SpriteRenderer ground.

  - The third-party store packs are imported but mostly unused by SampleScene.
